# Rosetta proof scores

These scores demonstrate a pattern through artifacts and validation gates. Eleven are copied into this examples directory; fourteen live only in the [corpus](../../scores/rosetta-corpus/proof-scores/). A passing `mzt validate` checks score structure, not provider credentials, API access, publication rights, or the proof's live result. Run from the repository root, read the score's header and variables, and budget for the named external services before starting.

The short proofs below carry their authors' approximate times. Long scores have no dependable wall-time estimate: provider queues, external APIs, builds, and deployment waits determine elapsed time. A paid model route is required wherever a score names Claude Code, Codex CLI, OpenCode, or another paid backend; configure and verify the routes it actually selects. The six long-tail proofs marked offline need only a configured role-class instrument chain, Python 3 and the sibling `tools/long_tail_proof.py` — no data downloads or publication credentials; their gates check artifact structure and joins, not semantic quality.

The corpus-only links are source proofs, not copied examples. `CL_TOKEN` and publishing credentials cannot be inferred from a passing local validation; read each score's admission gate before committing to a long run. A pattern's `proof_score:` frontmatter in the corpus points at its proof here or in `proof-scores/`; `python3 -I scores/rosetta-corpus/tools/unproven.py scores/rosetta-corpus` reports which patterns remain unproven, and its `--usage` mode counts citations across produced score YAML.
